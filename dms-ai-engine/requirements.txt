# Pinned 2026-07-28 after verifying real behavior on both Windows (dev) and Linux
# (container). Do not add a separate opencv-python/opencv-python-headless line:
# mediapipe pulls opencv-contrib-python transitively (a superset covering every
# cv2 API this repo uses — solvePnP, Rodrigues, VideoCapture, cvtColor), and
# installing a second cv2-providing package alongside it causes an import
# conflict on Linux (confirmed: ImportError: libxcb.so.1, even with
# opencv-python-headless, because mediapipe's own opencv-contrib-python wins
# the shared cv2 namespace anyway).
#
# mediapipe==0.10.14 is pinned (not the latest 1.0.0/0.10.35) because it is the
# version this repo's Face Landmarker migration was actually verified against.
# main.py no longer uses the legacy `mp.solutions.face_mesh.FaceMesh()` API at
# all -- that backend was fully replaced by the Tasks API (see "Tasks API
# verification" below); a grep for `mp.solutions` across dms-ai-engine/ returns
# nothing. The pin exists purely to lock in a version whose Tasks API surface
# was hands-on verified to work end-to-end, not to preserve any legacy
# `mediapipe.solutions` dependency. System libs required either way (Linux
# container): libgl1, libglib2.0-0, libsm6, libxext6, libxrender1, libxcb1,
# libgomp1 (see ../Dockerfile).
#
# Tasks API verification (2026-07-29): confirmed mediapipe==0.10.14 exposes
# the Tasks API surface this repo's real (non-mock) pipeline needs --
# mediapipe.tasks.python.vision.FaceLandmarker /
# vision.FaceLandmarkerOptions(output_facial_transformation_matrixes=True,
# output_face_blendshapes=True) -- construct without error on both Windows
# (dev machine, Python 3.12.1) and Linux (python:3.12-slim container, same
# system libs as this Dockerfile). Constructing FaceLandmarkerOptions doesn't
# require model_asset_path to point at a real file -- only create_from_options
# does, which is why the model bundle is fetched separately at Docker build
# time (see Dockerfile). No version bump beyond 0.10.14 has been needed since
# this migration landed; if a future upgrade is considered, re-verify
# FaceLandmarkerOptions construction on both platforms before bumping (1.0.0/
# 0.10.35 have not been tried against this repo's actual usage).
#
# face_landmarker.task model bundle (2026-07-29, updated): the Dockerfile
# fetches this from the version-pinned path
# .../face_landmarker/face_landmarker/float16/1/face_landmarker.task, not
# .../float16/latest/ -- `latest` is a moving alias and would let a future
# rebuild silently swap in a different model artifact with no build failure.
# Version 1 was confirmed to be exactly the artifact `latest` pointed at on
# 2026-07-29 (identical Content-Length 3758596 bytes and identical ETag/MD5
# b0e7274907a1644404fef66b28dd6d85 / sOcnSQehZEQE/vZrKN1thQ==). Bumping to a
# future face_landmarker v2, if MediaPipe ever publishes one, is a deliberate
# edit to the Dockerfile URL, not something that happens on its own.
